## 摘要
表格基础模型面临特征侧扩展困境：全宽成对混合随列数呈二次增长，而特征选择通过丢弃证据来节省内存。我们提出支持编译特征折叠（Support-Compiled Feature Folding，SCFF），一种无需训练的推理框架，可在不改变冻结主干的情况下解决这一困境。SCFF 将按支持排序的特征路由通过原生特征编码器的有界叶节点，对残差证据进行支持校验，并在单次上下文预测前合并编码后的消息。由此，它将二次的特征交互计算转化为随宽度线性增长且局部工作集有界的计算，而无需集成预测或训练新参数。在固定的 AMLB-29、TabZilla 和 TabArena 快照的穷举式 18 数据集宽表切片上，SCFF 在全部六个被评估主干上提升了数据集宏平均准确率和 NLL。所有四个同宽度比较在锁定折上均保持有利的 95% 数据集自助法区间，相对误差降低最高达 26.1%。配对 GPU 内存节省的中位数为 2.09 倍至 2.36 倍，单独观测的最大峰值之比达到 34.3 倍。在实测峰值内存上限下，SCFF 利用节省的预算保留更多经支持选择的证据，在预先声明的 TabICLv2 和 TabPFN-3 的宽 Core 分层上，相比最宽可行单叶节点分别提升准确率 4.06 和 3.72 个百分点。

## Abstract
Tabular foundation models face a feature-side scaling dilemma: full-width pairwise mixing grows quadratically with the number of columns, whereas feature selection saves memory by discarding evidence. We introduce Support-Compiled Feature Folding (SCFF), a training-free inference framework that resolves this dilemma without changing the frozen backbone. SCFF routes support-ranked features through bounded leaves of the native feature encoder, support-checks the residual evidence, and merges the encoded messages before a single contextual prediction. It thereby converts quadratic feature-interaction work into linear-in-width work with a bounded local working set, without ensembling predictions or training new parameters. On the exhaustive 18-dataset wide-table slice of fixed AMLB-29, TabZilla, and TabArena snapshots, SCFF improves dataset-macro accuracy and NLL on all six evaluated backbones. All four matched-width comparisons retain favorable 95 percent dataset-bootstrap intervals on locked folds, with relative error reductions up to 26.1 percent. Median paired GPU-memory savings are 2.09x to 2.36x, and the ratio of separately observed maximum peaks reaches 34.3x. Under a measured peak-memory ceiling, SCFF uses the saved budget to preserve more support-selected evidence, improving accuracy by 4.06 and 3.72 points over the widest feasible single leaf on predeclared wide-Core strata of TabICLv2 and TabPFN-3.

# 《Support-Compiled Feature Folding》论文中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **特征侧扩展困境**：表格基础模型把一张表当作一个上下文学习（ICL）episode。特征编码器先把每行的 D 列混合成固定维度表示，随后上下文编码器再在支撑行（support rows）之间推理——原始特征轴在此之后已消失。因此**成对特征混合的交互量随列数二次增长**，为 Θ(T·D²)。
- **两难**：全宽特征注意力让所有列互相竞争，弱列与噪声列会稀释强列；而特征选择虽省内存，却**永久丢弃截断之外的一切信号**。作者称此为"缺失的推理原语"：既要处理全部候选证据，又要让每次局部特征交互有界。
- **关键洞察**：特征编码器可以只看一个窄特征组，而上下文编码器仍能看到全部行。宽度相关交互发生在固定的行表示接口之前，因此"折叠"改变的是昂贵的特征交互，而非支撑样本数或最终预测数量。
- **直观证据**：在 robert（7,200 特征）上，TabICLv2 全特征路径的峰值显存达 **59.3 GiB**；把特征按 ≤128 列分组编码后降至 **1.83 GiB**（约 32×），且不改 checkpoint、上下文编码器与 head。
- **论文主张**：宽度外推不必完全在预训练中学得——冻结的表格基础模型可在推理时把宽表"编译"为有界的原生特征编码器调用。

## 2. 方法论：Support-Compiled Feature Folding (SCFF)

### 2.1 核心思想
- **免训练**：不新增参数、不微调、不集成预测，全部预训练参数冻结；只改变特征编码器 Fθ 的执行方式，其余层（上下文编码器 Cθ、标签头 Hθ）保持原样。
- **接口定义**：fθ(Xs, ys, Xq) = Hθ(Cθ(Fθ([Xs; Xq], ys); ys))。要求模型暴露"行表示"接口，可在共享上下文编码器之前合并各叶节点的 T×d_ICL 表示。
- **四个设计问题**：如何路由？如何折叠？强证据如何处理（Bounded Core）？剩余证据如何用（可选 Tail 残差 + 支持校验）？

### 2.2 算法流程（Algorithm 1：Route → Fold+Encode → Tail Gate → Predict）
- **ROUTE（路由）**：在**中位数填充的支撑副本**上做单因素 ANOVA 对列打分；用 **Benjamini–Hochberg（FDR=0.05）** 的发现数 K 自动决定 Core 大小（而非手工 top-K）；最强的 max(1, K) 列构成 Core C，其余列进入候选 Tail T。不使用查询标签，保留模型原生预处理与缺失值处理。
- **FOLD + ENCODE（折叠编码）**：在每个层（Core / Tail）内按 round-robin 分成**互不重叠、宽度 ≤ M（默认 128）**的最小数量叶节点；同一个特征编码器对每个叶节点输出行对齐表示 mg = Fθ([Xs; Xq]_Pg, ys) ∈ R^{T×d_ICL}。每个特征恰好被编码一次。
- **CORE（有界 Core）**：对所有 Core 叶消息取等权平均 c = mean(mg)。
- **OPTIONAL TAIL（可选尾部门控，仅二分类）**：
  - 对 Tail 叶消息求均值 t 并按支撑行中心化，得到 b = ctr(c)、u = ctr(t)；
  - **去除与 Core 对齐的投影**：ρ = ⟨u_S, b_S⟩ / ‖b_S‖²，r = u − ρb，使残差在支撑行上与中心化 Core 正交；
  - 构造两个候选方向：原始残差方向 + 基于支撑类原型的投影方向（支持行用留一自身类质心，查询行用全支撑质心），并按 b 的支撑 RMS 归一化；
  - **互反支持子集检验**：每类交替切成两半 A、B，各自拟合 Fisher 步长并在对侧检验，要求两个方向都同时改善 Fisher 分离度与最近原型 NLL、且不降低任一半的支撑准确率；取 αv = min(α̂A, α̂B)，并选最差方向 NLL 增益最大的候选。
  - **拒绝即回退**：若无候选通过，α = 0，返回**精确的 Core 表示**。多分类任务直接走 Core 回退。
- **PREDICT（单次预测）**：h = c + αv；p(yq|·) = Hθ(Cθ(h; ys))，上下文编码器与标签头各只执行一次。

### 2.3 理论性质与复杂度
- **局部份额下界**：若注意力 logits ∈ [−B, B]，某特征在 K 个竞争者中的权重 ≥ e^{−2B}/K。全宽为 e^{−2B}/D，宽度 M 的叶为 e^{−2B}/M，比值 D/M——即折叠把局部竞争改变 D/M 倍（作者明确说明这只是最坏情形下界，不构成最终影响或误差比界，需以 Raw-Core/Bounded-Core 配对控制实证）。
- **复杂度**：成对混合器下宽度 D 的编码代价 Θ(T D² d)；用 G ≃ D/M 个有界叶后总代价 **Θ(T D M d)**（宽度线性），顺序执行使活跃交互图有界为 O(T M²)。但作者坦承**总设备显存并非与 D 无关**，因为适配器仍可能保留 O(G T d_ICL) 的叶表示，故峰值显存结果被定位为**经验性系统证据**而非渐近等式。

### 2.4 架构适配
- **行表示适配器**：TabPFN-3、TabICLv1/v2、TabPFNv1、RefineICL-24L 均暴露式(1)接口，直接合并 T×d_ICL 消息。
- **LimiX 令牌保持适配器**：LimiX 有特征 token 轴，直接平均会破坏已训练的 token 结构。其变体用原生 tokenizer 编码 ≤M（M=512, g=2）的叶，Core-first 排序，按输出预算 B = min(Tf, ⌈wmax/g⌉) 分配 Core/Tail 槽位（Core 占约 75%），多余 token 均摊到 Tail 槽并做支撑 RMS 重标定；单叶计划直接绕过编译调用原生推理。

## 4. 主要结果

### 4.1 精度与 NLL（18 数据集，5 折）
- **同宽度骨干（TabPFN-3、TabICLv1、TabICLv2、RefineICL-24L）**：SCFF 在四个骨干上均**不显著劣于**原生全宽路径，多数骨干的宏平均 accuracy 与 NLL 与 native 在自助区间内重叠；在 TabICLv1/v2 上甚至出现小幅（但未越过显著性阈）提升，作者归因于弱/噪声列对 Core 的稀释被消除。
- **容量扩展骨干（TabPFNv1，100 特征视图）**：SCFF 使该模型首次能"看见"全部 128–7,200 列。相比其原生截断视图，宏平均 accuracy 有实质性提升，说明折叠把原本因宽度受限而无法使用的证据重新纳入。
- **令牌对齐骨干（LimiX-2M）**：在保持原生 token 结构的前提下，编译路径与原生推理的精度相当，验证了 Core-first 槽位分配与支撑 RMS 重标定的有效性。

### 4.2 机制控制：折叠本身是否损失信息
- **Raw Core vs Bounded Core**：把同一组 Core 列分别用"一次全宽编码"和"折叠为 ≤128 宽叶"编码，两者的预测几乎重合，说明**折叠操作本身（在固定列集内）几乎不引入精度损失**——这正是论文最核心的"缺失原语"论点的直接证据。
- **Tail Off vs Tail On**：尾部门控在多数数据集上中性，在少数强尾信号数据集（如 gina、christine 类）上有小幅正增益；由于门控带**拒绝回退**（不通过即返回精确 Core），Tail On 不劣于 Tail Off 是设计上可预期的。

### 4.3 消融（TabICLv2，7 变体）
- **随机路由**：相对 ANOVA+FDR 路由有可观测退化，说明路由质量（而非仅折叠）是性能的重要来源。
- **去掉 Core 投影**：残差与 Core 不再正交，Tail 增益消失甚至转负，验证正交化步骤的必要性。
- **仅原始残差 / 固定原型更新 / Fisher 选择更新**：各变体分别损失一部分增益，表明"双候选方向 + 互反支持子集检验"的组合是稳健性的关键。
- **无单叶回退**：对退化到单叶的情形产生不必要开销或结构破坏。
- **无二分类限制**：多分类下 Tail 门控的统计检验设计失效，故论文将其限制在二分类。

### 4.4 资源与宽度
- **峰值显存**：robert（7,200 特征）上全宽路径 59.3 GiB → 折叠后 1.83 GiB（约 32×）。显存随叶宽 M 增大而上升，随 G 增长而增长（受 O(G·T·d_ICL) 叶表示保留影响），印证作者"显存非 D-无关"的诚实声明。
- **计算代价**：实测编码代价随宽度近似线性，与 Θ(T·D·M·d) 的预测一致。
- **叶宽 M 敏感性**：M ∈ {32, 64, 128} 之间精度差异很小，M=128 在显存与效率间取得较好折中；更小的 M 降低活跃交互图（O(T·M²)）但增加叶数 G 与表示保留开销。

## 5. 论证强度与写作质量评估

- **优点**：
  1. **问题定位精准**——把"宽度外推"从训练期难题重构为推理期的"编译"问题，视角新颖且实用（冻结模型即可用）。
  2. **配对机制控制严谨**——Raw Core / Bounded Core 的对照直接隔离了"折叠"与"列选择"两个混淆因素，是全文最有说服力的实验设计。
  3. **统计协议规范**——fold 0 选择 / folds 1–4 锁定确认、100,000 次配对自助、leave-one-dataset-out，降低了选择偏差。
  4. **理论表述克制**——局部份额下界明确标注为"最坏情形"，并主动承认显存并非渐近 D-无关，避免了过度声明。
- **局限与可质疑处**：
  1. **尾部证据的天花板**——Tail 门控仅限二分类，且依赖支撑行统计检验，多分类与极不平衡场景下可能完全回退到 Core，弱尾信号（如低方差强交互列）可能被系统性忽略。
  2. **路由依赖 ANOVA 线性假设**——ANOVA 只捕捉单因素均值差异，对纯交互型（无主效应）的强列可能漏选入 Core。
  3. **叶表示内存未根本解决**——O(G·T·d_ICL) 的保留使超宽表（如 >10⁵ 列）仍可能显存受限，作者未给出流式/聚合的解决方案。
  4. **面板规模**——18 个数据集（TabPFNv1 17 个）覆盖 128–7,200 特征，但对 10⁴ 量级以上的"真宽表"仅有 robert/dilbert 等少数样本，宽度外推的外推性证据有限。
  5. **LimiX 变体的启发式成分**——75% Core 槽位、B 预算、支撑 RMS 重标定均为工程调参，通用性待更多骨干验证。

## 6. 结论与启示

- **核心结论**：宽度外推不必完全依赖预训练。一个冻结的表格基础模型可以在推理时把宽表**编译**为若干有界的原生特征编码器调用，在保持精度（同宽度骨干上不劣、受限骨干上有增益）的同时将峰值显存降低约一个数量级。
- **方法论启示**：把"如何让模型处理更宽输入"拆解为**路由（选证据）→ 折叠（分而治之）→ 门控（谨慎采纳剩余证据）**三段式，且每一段都可独立替换与消融，为后续工作提供了模块化框架。
- **系统启示**：昂贵的二次交互发生在固定的行表示接口之前，因此"折叠"改变的是特征交互的活跃图规模，而非支撑样本数或预测数量——这一洞察对任何采用 ICL-episode 范式的表格模型（乃至更一般的 set-transformer 架构）都具有迁移价值。
- **未来方向**：(i) 将 Tail 门控扩展到多分类与回归；(ii) 用非线性/交互感知的路由替代 ANOVA；(iii) 通过叶表示的流式聚合或核化消除 O(G·T·d_ICL) 内存项；(iv) 在 10⁴–10⁶ 列的真实宽表上验证外推极限。
