## 摘要
表格数据的基础模型近年来取得了显著进展，其中TabICLv2在多个表格分类任务上报告了最先进的性能。然而，全上下文的表格上下文学习仍然面临注意力成本随训练上下文大小增长的问题，这限制了其高效处理大型数据集的能力。Localized TabICLv2引入了一种方法，通过仅为每个测试点检索k个最近的训练邻居（基于模型Stage 2行表示空间中的相似度度量）来降低TabICLv2的推理成本，而不是使用完整的训练上下文。这不需要架构更改，并且我们表明可以通过额外的Stage 2和Stage 3微调来提高准确率保留率。在TabArena分类任务上，微调后的局部模型保留了全量TabICLv2准确率的98.64%，在批量推理中实现了2.18倍的中位加速，在单查询服务设置中达到了约249倍的中位加速。

## Abstract
Foundational models for tabular data have made significant progress in recent years, with TabICLv2 reporting state-of-the-art performance on several tabular classification tasks. However, full-context tabular ICL still suffers from attention cost that grows with the training-context size, which limits its ability to handle large datasets efficiently. Localized TabICLv2 introduces a method that reduces the inference cost of TabICLv2 by retrieving only the k nearest training neighbours for each test point, measured by similarity in the model's Stage 2 row-representation space, rather than using the full training context. This requires no architectural changes, and we show that accuracy retention can be improved through additional Stage 2 and Stage 3 fine-tuning. On TabArena classification tasks, the fine-tuned localized model retains 98.64% of Full TabICLv2 accuracy and it achieves a median 2.18$\times$ speedup in batch inference, and reaches approximately 249$\times$ median speedup in the single-query serving setting.

## 2. 论文提出的方法论

**核心思想**：对每个测试数据点，只在 Stage 2 学习到的行表示空间中检索 k 个最近的训练样本作为局部上下文，送入 Stage 3 进行 ICL 推理，从而将上下文长度从"整个训练集"压缩到固定的 k 个邻居，注意力成本从随训练集规模增长变为固定常数。

**模型结构（三阶段流程）**：
1. **Stage 1**：通过分布感知的列嵌入（column-wise embedding）生成列表示；
2. **Stage 2**：行交互建模，产出每行的向量表示（**被用作检索空间**）；
3. **Stage 3（TFicl）**：利用带标签的支持样本对查询样本进行 ICL 预测，仅接收检索出的局部上下文。

**关键技术要点**：
- **推理流程**：初始化 TabICLv2 分类器时设置 `kv cache = 'repr'` 并执行 `fit()`，Stage 1–2 只运行一次，行表示被缓存。预测时只用缓存列表示生成测试点嵌入，然后用 **余弦相似度 k-NN** 在每个测试点的 Stage 2 表示空间中检索 top-k 训练样本，最终仅将 k 个检索样本作为 Stage 3 上下文。
- **Stage 2+3 联合微调**：
  - 冻结 Stage 1（列嵌入），微调 Stage 2（行表示）与 Stage 3（ICL 预测器），以提升检索质量与局部推理下的精度保持；
  - 使用来自 `mix_scm` 先验的合成数据训练，序列长度在 10k–30k 间按 log-uniform 采样；
  - 批量大小 64，每张合成表一个梯度步；
  - 优化器：AdamW，**差分学习率**——Stage 2 用较低学习率（2×10⁻⁷）保留预训练表示，Stage 3 用较高学习率（2×10⁻⁶）；
  - 梯度裁剪最大范数 1.0，常数学习率调度。
- **复杂度分析（附录 A）**：
  - Full TabICLv2 Stage 3 复杂度：*O(N_train² + N_train·N_test)*
  - Localized TabICLv2 Stage 3 复杂度：*O(N_test·k²)*
  - 理论上当 N_test ≪ N_train 时，加速比约为 *N_train(N_train + N_test)/(N_test·k²)*，可达到很大的理论加速；但实际墙钟加速还受检索开销、batch 结构、内核启动、FlashAttention 对大序列的优化及数据搬运等因素影响，不能直接等同。

## 6. 论文的主要结论与发现

1. **k 的权衡关系**：k 增大时精度保留率单调上升，但加速比下降；k = 32 是精度与效率的实用平衡点（97.57% 精度保留，平均 1.97× 加速）。
2. **微调显著缩小精度差距**：S2+S3 微调将整体准确率从预训练局部模型的 97.31% 提升至 **98.64%** 保留率，恢复了到全上下文模型差距的约 49.5%；在 38 个数据集中的 33 个上优于未微调版本。
3. **Embedding 检索空间更优**：在 Stage 2 表示空间中检索（Embed FT）全面优于原始特征空间检索（Raw FT），证实了学习到的行表示是更好的检索基础。
4. **批量推理加速**：在 15 个大型 TabArena 数据集上取得 **中位 2.18× 加速**；在 credit-card-fraud 受控实验中，加速比随训练集规模增大呈单调增长趋势（10K 时 1.07× → 228K 时 3.46×），确认了局部化在大规模场景中的优势。
5. **低延迟场景收益显著**：单查询场景中位加速约 **249×**（最大单查询加速 1223×）；全上下文模型单查询延迟 ~76 秒（N ≈ 228K）而局部模型仅 ~59 ms。
6. **ICL 头不可替代**：在相同检索上下文中，Localized TabICLv2 以 37/38 的胜率同时击败 XGBoost-on-kNN 与 k-NN 多数投票，证明 ICL 组件超越了简单的标签聚合。
7. **整体定位**：Localized TabICLv2 在精度上未能超越全上下文模型，但在效率收益下精度损失较小（FT 后 98.64% 保留率），且微调后的模型在 AUC 与 log-loss 上**均超过了全量训练的 XGBoost**，无需超参数调整。

## 8. 不足与局限

- **精度仍有损失**：Localized 无法达到 Full TabICLv2 的精度（FT 后仍保留约 98.6%，掉了约 1.4 个百分点），对高精度敏感的任务存在风险；
- **检索失败风险**：当对预测有用的证据不在 k 个最近邻中时，模型可能丢失关键信息，论文未讨论这种情况的发生频率与缓解办法；
- **速度优势受条件限制**：小数据集或大批量查询时，检索开销和数据搬运会显著削弱加速效果（如 MagicTelescope 数据上仅为 0.77×，甚至慢于全上下文）；
- **多分类任务精度保留较弱**：从附录可以看出，多分类任务的 log-loss 恶化比二分类 AUC 更明显（如 MIC 数据集 0.5116 → 0.5943），对类别不平衡或类别数较多的场景需谨慎；
- **评估覆盖不足**：未覆盖回归任务、未与 LoCalPFN 等同类方法直接对比、未评估 FAISS 等高效检索后端、k 取固定值而非自适应；
- **算力信息披露不足**：未说明微调的总训练时长和 GPU 数量，难以评估方法本身的前期训练成本；
- **单作者工作**，未经过大规模同行评审（ICML 研讨会论文），部分声明（如与 TabICLv2 精度差距的具体恢复百分比）建立在较窄的评估维度之上。
