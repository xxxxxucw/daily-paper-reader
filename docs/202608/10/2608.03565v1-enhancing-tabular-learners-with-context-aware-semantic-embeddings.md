## 摘要
虽然现代表格学习器擅长捕获统计模式，但它们经常在语义真空中运行，将文本特征视为离散符号，忽略了特征名称或单元格条目中固有的丰富语义。我们提出了CASE（上下文感知语义嵌入），一个新颖的框架，弥合了大型语言模型（LLMs）的语义理解与表格学习器的统计能力之间的差距。与现有方法孤立地嵌入行不同，CASE采用了一种上下文化策略：我们用具有代表性的行样本预填充一个基于Gemma 3定制训练的表格语言模型的KV缓存，以建立数据集语义的持久锚点。这确保了生成的行嵌入是动态上下文化的，解决了语义歧义，并将表示锚定在特定领域的上下文中。我们在多个基准测试（CARTE、TextTab和TabArena）上的实验表明，CASE显著提高了表格学习器在语义丰富数据集上的性能，尤其是在低数据场景下。

## Abstract
While modern tabular learners excel at capturing statistical patterns, they frequently operate in a semantic vacuum, treating textual features as discrete symbols, ignoring the rich semantics inherent in feature names or cell entries. We propose CASE (Context-Aware Semantic Embeddings), a novel framework that bridges the gap between the semantic understanding of Large Language Models (LLMs) and the statistical capabilities of tabular learners. Unlike existing methods that embed rows in isolation, CASE utilizes a contextualization strategy: we pre-fill the KV cache of a custom-trained Gemma 3-based Tabular Language Model with a representative sample of rows to establish a persistent anchor of the dataset's semantics. This ensures that generated row embeddings are dynamically contextualized, resolving semantic ambiguities and anchoring representations in domain-specific context. Our experiments across several benchmarks (CARTE, TextTab, and TabArena) demonstrate that CASE substantially improves the performance of tabular learners on semantically rich datasets, particularly in low-data regimes.

## 1. 核心问题与整体含义（研究动机与背景）

现代表格学习器（如 GBDT、TabPFN 等）在捕获表格数据中的统计模式方面表现出色，但其本质上是“语义真空”的——它们将文本形式的特征（如列头名称、分类值、自由文本列）视为离散符号，无法利用其蕴含的丰富语义，也无法原生处理自由文本列。另一方面，大型语言模型（LLMs）虽然具备丰富的世界知识，但受限于表格序列化与 token 化效率低下，难以原生直接作为表格预测器处理大规模表格数据。因此，如何将 LLM 的语义理解能力与表格学习器的统计建模能力有效结合，是本文要解决的核心问题。论文提出的 CASE 框架旨在弥合这一差距，让表格学习器在保持统计推理能力的同时，获得语义感知能力，从而在语义丰富的表格数据上取得更好的预测表现。

## 2. 提出的方法论（CASE 框架）

CASE 框架的核心思路是：通过一个表格语言模型（TLM）为每行数据生成**上下文感知的语义嵌入**，并将该嵌入作为额外的特征列添加到原始特征矩阵中，供任意下游表格学习器使用。具体技术细节如下：

### 2.1 TLM 预训练阶段

- **表序列化与 Token 化**：将每张表序列化为连续的 token 序列。序列以包含所有列名的表头序列 `H = c1 ∥ [EOC] ∥ c2 ∥ ... ∥ cF+1 ∥ [EOR]` 开头，随后依次拼接每一行。每行按列序列化为 `S(ri) = vi,1 ∥ [EOC] ∥ ... ∥ vi,F ∥ [EOC] ∥ [BOT] ∥ yi ∥ [EOR]`，其中 `[EOC]` 为单元格分隔符、`[EOR]` 为行结束符、`[BOT]` 为目标值起始标记。数值目标被规范化为科学计数法字符串。
- **训练目标**：以 Gemma 3 解码器（非指令微调版本）为初始化权重，继续进行自回归无监督预训练，但**仅对目标列（target column）的 token 计算 next-token prediction loss**，损失函数为 `L(θ) = -Σ_{t∈I_target} log P(s_t | s<t; θ)`。这迫使模型在预测目标列时，同时利用特征信息与数据集的整体上下文统计信息。
- **训练数据与设置**：使用大规模真实世界 T4 表语料库；每步随机抽取 256 行、指定一个目标列；训练了 270M、1B、4B、12B 四种参数规模的模型，各训练 8500 步，batch size 为 128，总计约 2.8 亿行；学习率 1e-6，无 dropout 和 weight decay，输入最长截断为 16k token。

### 2.2 上下文感知的行嵌入提取（表增强）阶段

- **Context Priming（上下文启动）**：从训练集中随机采样 k=128 行作为上下文样本（包含特征与目标列），将其序列化并通过 TLM 前向传播后，**保留模型的 KV cache 作为持久前缀**。该 cache 锚定了数据集的全局语义分布与预测任务。
- **行嵌入提取**：将每个目标测试行依次送入模型，复用预填充的 KV cache，提取最后一层隐藏层在 `[BOT]` 位置上的向量作为该行的上下文感知嵌入。
- **表增强**：对提取的嵌入集合做 PCA 降维（投影到 32 维），将降维后的语义特征与原始特征拼接：`X' = [X_org ∥ PCA(E)]`。PCA 仅在训练分布上拟合，用于测试嵌入以保证无数据泄漏。

## 6. 主要结论与发现

1. **CASE 大幅提升语义丰富表格数据上的预测性能**：在 CARTE 和 TextTab 上，分类准确率提升 2.9%～6.8%，R² 提升 3.8%～19.1%；TabICLv2 + CASE 全面超越 AutoGluon 等强基线，在 CARTE 和 TextTab 上排名第一。
2. **上下文启动（Context Priming）至关重要**：从 0 token 到 1k token 的上下文跨越带来了显著的“上下文化跳跃”，证明单行孤立嵌入在语义上存在内在歧义。
3. **低数据场景优势突出**：在 CARTE 训练集子采样（128～8k 行）实验中，CASE 在低数据区域不仅显著优于既有方法，其性能跌幅也小于传统预测器，表明 LLM 语义先验有效补偿了稀疏统计信号。
4. **参数规模与性能呈单调正相关**：TLM 从 270M 到 12B 逐步提升语义嵌入质量，符合 LLM scaling law。
5. **CASE 对随机上下文选择的鲁棒性高**：5 个随机种子上的性能方差极小，说明模型成功提炼了全局语义分布，而不是依赖特定锚点行。
6. **语义驱动而非记忆驱动**：语义破坏性测试中，列头和字符串被替换密码毁坏后，CASE 几乎退化为纯非语义基线，证明其增益源于真实语义理解而非单纯统计捷径。
7. **在数值密集的 TabArena 上性能有所回退**：原始 TabICLv2 在这些任务上保持优势，表明 CASE 是面向语义丰富场景的模块化增强器，可按需选择性使用。

## 7. 优点（方法或实验设计亮点）

- **架构新颖且工程高效**：利用 KV cache 预填充而非重复编码上下文，规避了 LLM 自回归解码的巨大开销；一次前向传播即可获得嵌入，在线推理延迟低于 TF-IDF 方案（因下游特征维度恒定为 32 而非 32×列数）。
- **即插即用**：与任何表格学习器均可无缝集成（只要支持数值特征拼接），无需改动下游模型结构；CASE 嵌入的 PCA 压缩使其成为轻量级特征增强手段。
- **目标感知嵌入**：与现有孤立单元格嵌入（如 ConTextTab、MiniLM）不同，CASE 嵌入的优化和提取均以目标列预测为导向，嵌入表示天然与预测任务对齐。
- **消融设计的因果性**：通过语义破坏性测试和“K=0 vs K>0”的双重对照，严格证明了语义信息与上下文窗口各自对性能的独立贡献。
- **统计严谨**：大量使用了 Friedman + Nemenyi 统计检验、关键差异图和重复随机种子实验。

## 8. 不足与局限

- **非排列不变性**：CASE 对行列顺序不具排列等变性（作者在附录 F 发现列排列不造成统计显著差异，但架构上并无保障）；解码器架构的位置编码使其对表格结构顺序天然敏感。
- **数值归纳偏差弱**：基于 token 的语言模型对连续的数值特征缺乏内在的数值偏序理解，数值目标被归一化为科学计数法字符串后，可能丢失部分精度信息。
- **随机上下文选择**：当前使用均匀随机采样铺满 KV cache，可能遗漏对分布定义至关重要的关键锚点行，存在信息覆盖不完整的风险（作者承认此限制）。
- **PCA 压缩可能不够最优**：线性降维可能损失嵌入中的非线性精细语义信息，未来可探索流形学习等方法。
- **客观的实验覆盖局限**：TabArena 上的性能回退虽然幅度小，但被统计检验标记为显著，论文将其视为“边界”，但在实际应用中需要用户自行判断数据语义密度；CARTE 分类任务以二分类为主，对多分类场景的结论推广需谨慎。
- **数据污染风险**：尽管作者通过 T4 语料重叠搜索与序号记忆验证实验做了间接否定性证据，但 Gemma 3 预言训练语料是专有的，无法完全排除测试集被污染的可能。
- **计算成本与复现门槛高**：训练 12B 参数级的 TLM 需要专用算力；虽然论文对比了推理延迟，但对训练资源的披露不够透明，全文未报告 GPU 数量与总训练时长，复现门槛较高。
