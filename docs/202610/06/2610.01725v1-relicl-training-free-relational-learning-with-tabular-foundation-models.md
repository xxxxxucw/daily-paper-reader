## 摘要
表格基础模型无需任何训练即可在单表任务上取得最先进的性能。近期研究表明，它们也适合通过深度特征合成（DFS）进行关系学习，DFS 通过将其他表的列聚合作为特征加入，从而将关系模式展平为单表。这种思路很有吸引力，因为它可以直接受益于底层表格基础模型的改进或定制。在本文中，我们指出 DFS 的两个关键问题：特征爆炸和交互盲区。第一个问题之所以出现，是因为随着模式变得更复杂，DFS 特征的数量会迅速增长，从而限制了可扩展性和性能。第二个问题之所以出现，是因为按列聚合没有考虑特征交互，从而限制了性能。我们提出并探索了一种称为 RelICL 的替代方法，它保留了 DFS 的优势，同时缓解了这两个问题。RelICL 的核心是沿着模式图逐步传播和融合信息，并使用最终用于预测的同一个表格基础模型来完成这一过程。在我们使用 RelBench 任务进行的实验研究中，RelICL 与基于深度特征合成的最强方法表现相当。

## Abstract
Tabular foundation models achieve state-of-the-art performance on single-table tasks without any training. Recent work suggests that they are also well-suited for relational learning via deep feature synthesis (DFS), which flattens a relational schema into a single table by adding aggregates of the other tables' columns as features. This approach is appealing because it directly benefits from improvements to or customization of the underlying tabular foundation model. In this paper, we identify two key problems with DFS: feature explosion and interaction blindness. The first problem arises because the number of DFS features grows quickly as the schema becomes more complex, limiting scalability and performance. The second problem arises because column-wise aggregates do not account for feature interactions, limiting performance. We propose and explore an alternative method termed RelICL, which keeps the benefits of DFS but alleviates these two problems. At its heart, RelICL propagates and fuses information step by step through the schema graph, using the same tabular foundation model that is eventually used for prediction to do so. In our experimental study using RelBench tasks, RelICL was on par with the strongest approach based on deep feature synthesis.

## 1. 核心问题与整体含义

- **研究背景**：表格基础模型（Tabular Foundation Models, TFMs）如 TabPFN、TabICL、TabFM 等，在单表任务上通过上下文学习即可达到 SOTA，无需额外训练。一个自然问题是：能否把这类强单表模型用于由多张表通过外键关联的关系数据库，即关系学习？
- **现有主流思路**：深度特征合成（Deep Feature Synthesis, DFS）将关系模式展平为单表。它沿 meta-path 从任务表出发，聚合上下文表中单列的值，生成额外 DFS 特征，再用任意表格模型（包括 TFM）预测。
- **DFS 的两个关键问题**：
  - **特征爆炸**：DFS 特征数随模式复杂度快速膨胀，数量级约为 `O(#meta-paths × #attributes × #aggregates)`，实践中常需限制 meta-path 深度或剪枝，从而损失信息。
  - **交互盲区**：每个 DFS 特征只是单列聚合，无法捕获上下文表列与列之间的交互。
- **论文的总体含义**：作者提出 RelICL，试图保留 DFS 的核心优势——免训练、可直接复用任意 TFM——同时规避特征爆炸和交互盲区。其核心是用同一个 TFM 同时完成特征提取、特征融合和最终预测。

## 2. 方法论

### 2.1 核心思想

- RelICL 不把上下文表列逐个聚合后拼接到任务表，而是：
  - 用 TFM 的编码器 `T_enc` 提取上下文表行的 **row embedding**；
  - 沿关系模式图逐步传播、池化和融合这些 row embedding；
  - 最终在扩展后的任务表 `T+` 上运行完整 TFM `T` 进行预测。
- 关键假设 **Asm.1**：`T(T_enc(R))` 的性能与 `T(R)` 接近，即行嵌入足以替代原始特征列。这样，融合 pooled row embeddings 不会显著损失信息。

- **问题设定**：给定关系数据库 `D`、任务表 `T` 的训练行 `T_train` 和查询行 `T_eval`，用预训练 TFM 预测 `T_eval` 的目标属性。时间型任务通过 cutoff 时间过滤未来行，并在池化时做 temporal pooling。
- **构建 inference DAG**：从任务表开始 BFS，得到有向无环图；边 `R → S` 表示表 `R` 的信息应融合进表 `S`。
- **阶段 1：向外遍历**：
