## 摘要
表格机器学习通常依赖于针对每个数据集的工作流程，为每个任务从头拟合树集成模型或运行 AutoML 搜索。我们提出 TabFM，一个 400M 参数的表格基础模型，将监督式表格预测形式化为上下文学习。TabFM 在单次前向传播中生成经过校准的零样本预测，无需任务特定调优。TabFM 完全在由结构因果模型生成的合成表格上训练，学习到可零样本迁移到真实世界任务的通用表格表示。在 TabArena 的全部 51 个基准数据集（38 个分类和 13 个回归）上，零样本 TabFM 在默认表格基础模型中排名第一，并优于经过调优的 AutoML 流水线。基于同一冻结权重的两个扩展进一步提升了两类任务上的性能：带集成和后校准的多视图特征扩展（TabFM+），以及由 LLM 引导的、针对特定数据集的数据处理和特征工程（TabFM-Auto）。

## Abstract
Tabular machine learning typically relies on per-dataset workflows, fitting tree ensembles or running AutoML searches from scratch for every task. We present TabFM, a 400M-parameter tabular foundation model that formulates supervised tabular prediction as in-context learning. TabFM produces calibrated zero-shot predictions in a single forward pass without task-specific tuning. Trained entirely on synthetic tables generated from structural causal models, TabFM learns general tabular representations that transfer zero-shot to real-world tasks. Across all 51 benchmark datasets in TabArena (38 classification and 13 regression), zero-shot TabFM ranks first among default tabular foundation models and outperforms tuned AutoML pipelines. Two extensions over the same frozen weights improve performance further on both tracks: multi-view feature expansion with ensembling and post-hoc calibration (TabFM+), and LLM-guided, dataset-specific data processing and feature engineering (TabFM-Auto).

# TabFM 论文中文总结

## 1. 核心问题与研究动机

- **背景痛点**：表格数据的监督学习长期依赖“逐数据集”工作流——为每个任务从头训练梯度提升树（GBDT）、随机森林，或运行 AutoML 搜索。每遇到一个新任务，都需要定制预处理、分裂点扫描与超参数搜索，成本高、难以复用。
- **范式转变**：基础模型（foundation model）的核心价值在于“摊销学习”——把学习成本压进一次前向传播。受 Prior-Data Fitted Networks（PFNs）启发，可用上下文学习（in-context learning）将监督预测参数化为一个通用后验预测映射：`f_θ(D_train, x_test) ≈ p(y_test | x_test, D_train)`。
- **核心挑战**：将上下文学习扩展到通用表格极为困难，主要源于三点：
  - 行是可交换的，模型必须具备置换等变性；
  - 列同时混合需要精细数值分辨率的连续值与无自然序的离散类别；
  - 朴素地对所有单元格做注意力复杂度为 `O(T²H²)`（T 行、H 列），历史上将表格 Transformer 限制在 1000 行以内。
- **整体含义**：TabFM 旨在证明“仅用合成因果数据预训练的表格基础模型，可零样本迁移到真实任务，并超越调参 AutoML”，从而改变表格机器学习的默认工作流。

## 2. 方法论

### 2.1 核心思想
将监督式表格预测形式化为上下文学习：输入一张表（含带标签的 context 行与无标签的 query 行），模型在单次前向传播中直接输出 query 行的校准预测，无需任何任务特定微调。

### 2.2 四阶段架构（总参数 408.7M，d_model=128）
- **① 频谱单元嵌入（Cell Embedder）**：
  - 采用**二元特征分组**（dyadic feature grouping），每个列 j 与偏移 0、1、3 的邻居列配对（组大小 G=3）；
  - 每个槽位 g 用一组 **32 个可学习傅里叶频率** `ω_g ∈ ℝ³²` 投影标量值，得到 64 维嵌入：`γ_g(v) = [cos(2πω_g,1 v), sin(2πω_g,1 v), …, cos(2πω_g,32 v), sin(2πω_g,32 v)]`；
  - 数值列与类别列走**独立频率库**（`ω_num` vs `ω_cat`）与独立投影矩阵，兼顾连续值的度量尺度与类别的离散映射；
  - 带标签行额外加入目标嵌入 `e(y_i)`，query 行不加。
- **② 交替的列/行注意力编码器**：
  - **列方向**使用 Induced Self-Attention Block（ISAB），以 m=256 个可学习诱导点压缩，将 `O(T²E)` 降为 `O(TmE)`；
  - **行方向**使用 Self-Attention Block（SAB），沿特征轴施加 **RoPE 旋转位置编码**，区分通道但不引入序关系，保持行的置换等变性；
  - 共两个不共享参数的 stage，每 stage 含 3 个 ISAB + 3 个 SAB；
  - 两个固定掩码：`M_pad`（特征填充掩码，H_max=100）与 `M_ctx`（上下文掩码，只允许带标签前缀作为 key）。
- **③ CLS 池化**：8 个可学习 CLS token 沿特征轴前置，最终状态拼接为 1024 维行表示 `r_i`，将任意特征数压缩为固定宽度。
- **④ 24 层上下文学习预测器**：宽度 1024、8 头、FFN 4096；带标签行再次注入目标嵌入，query 行目标嵌入置零。由于 `M_ctx` 屏蔽所有 `k > T_train`，每个测试行只关注带标签上下文，测试预测在给定 `D_train` 下条件独立，杜绝标签泄漏，且 query 块可拆分/重排而不影响结果。
- **⑤ 预测头**：2 层 MLP 输出分类 logits 或回归标量。

### 2.3 合成预训练与课程学习
- 训练数据**完全由结构因果模型（SCM）生成**：随机采样有向无环图，根变量从 4 种基础分布中抽取，经非线性变换与代数聚合（sum / prod / logsumexp / max）传播，生成混合连续与离散列、含缺失值、标签噪声、类别不平衡的表格，特征轴上限 100 列。
- 每张表在送入模型前即切分为带标签 context 与 query 块，损失只在 query 行上计算，与推理接口一致。
- **四阶段课程**：上下文从 2,048 扩展到 16,384 行，每次过渡行数翻倍、批大小减半，保持每步 token 数恒定为 `2²² ≈ 4.19M`，稳定优化。

### 2.4 两个扩展（冻结权重）
- **TabFM+**：推理时对同一冻结 checkpoint 运行 K=32 个变换视图——一半用原始列（上限 500 列），一半追加随机抽取的**乘法交叉特征**（⌊√H⌋ 对数值列乘积）与**截断 SVD 结构特征**（⌊√H⌋ 个主奇异向量）；每个成员独立施加不同预处理（标准缩放 / Yeo–Johnson 幂变换、4.0 处 z-score 离群裁剪）、随机列置换、类别索引双射置换、分类标签循环移位；用**非负最小二乘（NNLS）**堆叠权重并向均匀分布收缩（`w_final = 0.75w + 0.25/K`），分类加 Platt 校准。
- **TabFM-Auto**：冻结的 TabFM 与 Gemini-3.8-Flash 配对，LLM 在封闭的程序合成循环中迭代编写、评估、精炼 Python 数据管线（预处理、特征工程、context 行选择、预测后处理、推理设置）。TabFM 始终是主预测器，权重永不更新；每个候选程序在训练划分内做三折交叉验证（8 个集成成员），日志反馈给下一轮编辑；搜索在 96 次评估或 6 小时后停止。

### 2.5 复杂度
- 列注意力 `O(T·H·m·E)`（m=256），行注意力 `O(T·H²·E)`，预测器 `O(T²d)`（d=1024，只在池化行表示上做一次）。上下文可达 **16,384 个实例**，比早期上下文表格预测的规模高一个数量级。

## 6. 主要结论与发现

- **零样本 TabFM 领先默认基础模型**：分类 1768.6 Elo（超过 EXAONE-Tabular 的 1768.0、AutoGluon 1.5 extreme 的 1669.7、TabPFN-3 的 1641.9、TabICLv2 的 1586.4）；回归 2055.2 Elo（超过 EXAONE-Tabular 1973.1、TabPFN-3 1866.6、AutoGluon 1.5 extreme 1851.2）。
- **误差与遗憾更低**：分类 G-mean 0.0957、oracle improvability 6.10%（对比 EXAONE-Tabular 9.47%、AutoGluon 1.5 extreme 10.00%）；回归 G-mean 16.40、improvability 2.62%。
- **两两胜率**：对 EXAONE-Tabular 65.7%、对 AutoGluon 1.5 extreme 72.1%、对 TabPFN-3 75.9%、对 TabICLv2 79.8%，且胜率随 Elo 差单调增加。
- **扩展带来显著增益（权重全冻结）**：TabFM+ 增加分类 +69.4 Elo、回归 +134.0 Elo（回归增益约为分类两倍，因连续尺度上平均更能降方差）；TabFM-Auto 增加分类 +172.1 Elo、回归 +337.2 Elo，登顶两条赛道。
- **TabFM-Auto 的泛化性**：在 51 个数据集中改善 41 个（10 个改善超 10%），回归 13 个全部改善且达到 0.00% oracle improvability；未改善的 10 个分类数据集误差最多只增加 1.8%。
- **改进主要来自特征构造而非调参**：例如 airfoil_self_noise 上构造 Strouhal 数与 Reynolds 数、Diabetes130US 上将 ICD-9 诊断折叠为章节；有表格改动的运行中位误差降低 2.14%，无改动仅 0.27%。

## 7. 优点

- **架构设计针对性强**：用“二元特征分组 + 学习式傅里叶单元嵌入”解决连续值数值分辨率问题；用“列 ISAB（线性复杂度）+ 行 SAB（RoPE）”解耦跨样本推理与特征编码，把上下文从 <1000 行推到 16,384 行。
- **上下文学习机制干净**：非对称 `M_ctx` 掩码保证测试预测在给定训练集下条件独立，既防止标签泄漏，又允许 query 块拆分/重排，理论上与 PFN 的后验预测映射一致。
- **纯合成预训练即可零样本迁移**：完全基于 SCM 生成的合成表训练，却能在 51 个真实数据集上超越调参 AutoML，验证了因果先验作为归纳偏置的有效

性——把“因果生成过程”当作先验，比单纯堆真实数据更能塑造可迁移的表格归纳偏置。

- **扩展模块设计克制且可解释**：TabFM+ 与 TabFM-Auto 均在**完全冻结**主模型权重的前提下提升性能，明确把增益归因于“更好的输入表示/数据管线”而非“更强的拟合”。多视图中的乘法交叉特征与截断 SVD 结构特征分别对应“特征交互”与“低秩结构”两类经典表格先验；NNLS 堆叠 + 向均匀分布收缩（0.75/0.25）则是在“用验证集挑权重”与“防止过拟合到少数视图”之间取的稳健折中。
- **LLM 的定位清晰**：TabFM-Auto 把 LLM 限制在“写代码/改管线”的封闭程序合成循环里，主预测器始终是 TabFM，且候选程序在训练划分内做三折 CV、无法接触留出测试集。这种“LLM 当特征工程师而非预测器”的设计，既避免了 LLM 直接输出标签的不稳定与不可控，也保留了其领域知识（如把 ICD-9 折叠成章节、构造 Strouhal 数）的迁移价值。
- **评估方法论扎实**：使用 TabArena 这一持续更新的活基准，配合重复 10 折、Bradley–Terry Elo（RF=1000 锚定）、bootstrap 取中位数，并以 Improvability 量化“距 oracle 的剩余空间”，比单一平均精度更能揭示方法是否已接近该数据集的可达上限。
- **写作与可复现细节较完整**：给出精确参数量（408.7M）、d_model、诱导点数 m=256、CLS token 数、预测器层数与宽度、掩码语义、课程学习的 token 守恒策略，工程上具备较强的可重建性。

## 8. 局限与不足

- **算力信息缺失**：未报告预训练 GPU 型号、卡数、总 GPU 小时或数据生成吞吐，难以评估“摊销学习”的真实训练成本与碳足迹，也无法判断该方法对中小实验室的可及性。
- **对比预算不对等**：AutoML 基线为 4 小时，TabFM-Auto 为 6 小时（96 次评估或 6 小时），两者时间预算并不严格对齐，可能对 AutoGluon 等基线略有不公；若统一到 4 小时或 6 小时，排名是否变化未被讨论。
- **规模上限的硬约束**：模型特征轴上限 H_max=100，TabFM+ 放宽到 500 列；上下文上限 16,384 行。对于宽表（数千列）或超长表（百万行），仍需依赖外部降维/采样，论文未系统给出这些边界条件下的退化曲线。
- **合成先验的覆盖盲区**：训练数据完全来自 SCM 生成的表格，天然偏向“列间存在稀疏因果结构、数值/类别混合、有缺失与噪声”的分布。对文本列、时间戳/时间序列结构、多模态字段、图关系列、强层次结构等真实表格常见形态，SCM 先验是否充分未被验证，也存在合成分布被“过拟合”而真实任务上收益不均衡的风险。
- **TabFM-Auto 的依赖与成本**：性能依赖 Gemini-3.8-Flash 的具体版本与提示工程，LLM 版本更新可能导致结果漂移；程序合成循环需要执行候选代码，带来沙箱安全与计算开销，且 6 小时搜索成本在“零样本”卖点下显得不那么“免费”。
- **回归指标解读需谨慎**：回归 G-mean 为 16.40、improvability 仅 2.62%，说明 TabFM 在回归上已接近该基准的 oracle 上限，但也意味着不同方法间的 Elo 差距可能被少数高误差数据集放大；绝对误差量级是否在业务可接受范围内，需结合具体数据集判断。
- **消融深度有限**：缺少对“傅里叶频率数量（32）”“分组大小 G=3”“ISAB 诱导点数 m=256”“课程阶段数”等关键超参的系统消融，难以判断哪些设计是性能关键、哪些只是工程便利。
- **统计显著性**：报告了 bootstrap 中位数与胜率，但未给出配对显著性检验（如按数据集配对的 Wilcoxon 或校正后的 p 值），Elo 差较小的方法（如 TabFM 1768.6 vs EXAONE-Tabular 1768.0）是否统计可区分尚不明确。

## 9. 启示与展望

- **对表格 ML 工作流的影响**：若零样本 TabFM 能稳定匹敌甚至超过调参 AutoML，则“每个新表格任务先跑 AutoML”的默认流程可被“先跑一次前向传播”取代，AutoML 与特征工程的价值将更多体现在 TabFM+ / TabFM-Auto 这类“包裹层”上。
- **因果先验作为归纳偏置**：纯合成 SCM 数据训练即可迁移到真实表格，提示表格领域的“数据瓶颈”或许不是数据量，而是**生成过程的多样性**。未来可探索更丰富的结构先验（时序、层次、文本-数值混合）以拓展覆盖域。
- **冻结主干 + 可组合外挂**：TabFM+ 与 TabFM-Auto 展示了“不更新权重也能显著提升”的路径，这种模式在算力受限、需要审计与可复现的场景中尤具吸引力；也为“基础模型 + 检索/工具/程序合成”的通用范式提供了表格实例。
- **上下文长度的继续扩展**：当前 16,384 行已是早期上下文表格预测的一个数量级提升，但距离真实大表仍有差距；列向 ISAB 与行向 SAB 的解耦为继续扩展提供了可延展的复杂度骨架。
- **评估基础设施的价值**：TabArena 的“活基准 + 多指标 + oracle improvability”组合，为快速迭代的表格基础模型提供了一个可持续、抗过拟合的评测框架，值得其他子领域借鉴。

## 10. 一句话总结

TabFM 用“二元特征分组 + 学习式傅里叶单元嵌入 + 列 ISAB/行 SAB 交替编码 + 纯 SCM 合成预训练”，把表格监督预测变成了单次前向传播的上下文学习，在 TabArena 的 51 个数据集上以零样本姿态超越调参 AutoML 与同代表格基础模型，并通过冻结权重的多视图集成（TabFM+）与 LLM 引导的特征工程（TabFM-Auto）进一步登顶分类与回归两条赛道——其核心贡献不仅是一个更强的模型，更是对“表格机器学习默认工作流”的一次范式重写。
