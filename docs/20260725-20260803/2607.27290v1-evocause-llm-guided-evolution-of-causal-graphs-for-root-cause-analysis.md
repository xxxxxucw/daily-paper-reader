## 摘要
现代电信、云和微服务系统在组件故障时会发出关联的告警级联。根因分析旨在识别启动每个级联的一小组告警。一种常见的方法是从观测日志中学习因果图，并预测每个事件诱导子图中所有零入度的告警。然而，学习到的图保持固定，无法从专家对历史事件的诊断中获益。我们通过EvoCause来闭合这一循环。专家标签约束哪些告警应为源节点，但并未指定满足这些约束所需的边编辑。EvoCause使用大型语言模型（LLM）提出语义上合理的图编辑，同时确定性代码验证节点身份和无环性，并在标注对齐集上保留最佳图。在测试时，仅使用精炼后的图即可产生透明的预测，而无需调用LLM。我们还发布了TeleRCA，这是一个来自生产电信网络的专家标注基准，包含485,681条告警事件，跨越194种告警类型，涉及5,621个资源。在合成数据上，以PC因果发现算法初始化的EvoCause优于未精炼的PC基线，Node F1、Case EM和Graph F1分别提高了11.59、9.40和4.59个百分点，同时nSHD降低了0.2379。在TeleRCA上，将可读的告警标题替换为匿名标识符会使Node F1和Case EM分别下降6.12和8.04个百分点，表明告警名称信息对图精炼有所贡献。

## Abstract
Modern telecommunication, cloud, and microservice systems emit correlated alarm cascades when components fail. Root cause analysis (RCA) aims to identify the small set of alarms that initiate each cascade. A common approach learns a causal graph from observational logs and predicts all zero-in-degree alarms in each incident-induced subgraph. However, the learned graph remains fixed and cannot benefit from expert diagnoses of historical incidents. We close this loop with EvoCause. Expert labels constrain which alarms should be source nodes but do not specify the edge edits needed to satisfy those constraints. EvoCause uses a large language model (LLM) to propose semantically plausible graph edits, while deterministic code validates node identities and acyclicity and retains the best graph on a labeled alignment set. At test time, the refined graph alone produces transparent predictions without an LLM call. We also release TeleRCA, an expert-annotated benchmark from a production telecommunication network containing $485{,}681$ alarm events spanning $194$ alarm types over $5{,}621$ resources. On synthetic data, EvoCause initialized with the PC causal discovery algorithm outperforms the unrefined PC baseline, raising Node F1, Case EM, and Graph F1 by $11.59$, $9.40$, and $4.59$ percentage points, respectively, while reducing nSHD by $0.2379$. On TeleRCA, replacing human-readable alarm titles with anonymous identifiers lowers Node F1 and Case EM by $6.12$ and $8.04$ percentage points, respectively, indicating that alarm-name information contributes to graph refinement.

### 1. 论文的核心问题与整体含义

- **研究背景**：现代电信、云和微服务系统由大量紧耦合组件构成，单点故障会触发级联告警（即"告警风暴"）。根因分析（RCA）旨在从事件产生的告警序列中识别出真正需要处置的少量根因告警，而快速定位根因对降低故障影响至关重要。
- **既有方法的缺陷**：常见的因果方法将告警类型及其触发关系建模为有向无环图（DAG），预测每个事件诱导子图中的零入度节点作为根因。此类图通常由因果发现算法从观测日志中学习得到，但学习后的图**固定不变**，无法利用运维团队（SRE）积累的历史事件诊断经验来持续改进。此外，因果发现算法依赖较强假设，在真实生产告警流中容易产生虚假或缺失的边。
- **核心问题**：专家标注的根因标签仅指定了"哪些告警应为源节点"，但没有给出满足该约束所需的边增、删、改。这种反馈是间接且欠定的——同一组标签可能对应多个不同的图结构。如何利用这种任务级、稀疏的专家反馈来优化因果图，是本文要解决的核心问题。
- **整体含义**：本文提出的EvoCause框架将LLM引入因果图优化循环，用专家标注来引导因果图的演化，形成一个"发现—反馈—精炼"的闭环，使得因果图不再是一次性学习的静态产物，而是可以随历史诊断积累持续改进的动态结构。

### 2. 论文提出的方法论

#### 核心思想

EvoCause的核心思路是：**LLM提议、确定性代码验证、标注集择优**。LLM不是直接预测根因，而是在一个组合搜索空间中提出少量语义合理的图编辑候选；确定性程序负责验证编辑的合法性和图的无环性，并在标注对齐集上保留性能最优的图。LLM的语义理解能力与代码的严格校验相结合，既利用了告警名称等语义信息，又保证了结果的结构合法性。

#### 整体框架

EvoCause包含两个阶段：

- **学习阶段（离线）**：
  - **Stage I：初始APG构建**——使用任意现成的因果发现算法（PC、NOTEARS、THPs）从无标签历史告警序列 `D_hist` 中学习初始告警传播图 `G0 = CausalDiscovery(D_hist)`。
  - **Stage II：基于标签反馈的APG对齐与精炼**——使用专家标注的对齐集 `D_align`，通过多轮迭代优化图结构。每轮对一批标注事件执行四个步骤：
    1. **批量处理**：随机打乱对齐集，按批次 `N_b` 分组，聚合多个事件的反馈，降低对单个事件的敏感性。
    2. **用当前图预测**：对每个事件运行图结构的RCA引擎，得到预测根因集合 `ŷ_i`，与专家标注 `y_i` 比较产生失配信号。
    3. **LLM提议图编辑**：将当前图G、由G确定性导出的拓扑序O(G)、批量失配证据E、优化历史H一起输入LLM，由LLM输出一组边编辑操作 `ΔG = {add, remove, reverse}`。
    4. **验证并应用编辑**：解析器检查操作类型合法性和端点合法性，应用编辑后验证图仍为DAG，否则拒绝全部更新。每轮后在对齐集上计算得分（Case EM为主，Node F1为平局打破），保留最优图。
- **推理阶段（在线）**：仅使用精炼后的图 `G*`，对每个新事件提取其涉及的告警类型，取诱导子图中的零入度节点集合作为预测根因集合。**推理阶段不需要调用LLM，也不依赖专家标签**，每个预测均可追溯到图的具体边，具备可审计性。

#### 关键公式与定义

- **告警传播图**：`G = (A, E)`，节点为告警类型，边表示触发关系。
- **事件级源算子**：`Src_G(V_i) = {v ∈ V_i : Pa_G(v) ∩ V_i = ∅}`，即事件中无父节点的告警类型集合。
- **根因一致图集**：`C_RCC(D_L) = {G ∈ DAG(A) : Src_G(V_i) = y_i, ∀i}`，即对所有标注事件都产生正确源节点集的图集合。
- **经验不一致度**：`L_RCA(G, D_L) = (1/m) Σ 1{Src_G(V_i) ≠ y_i}`，用于量化图与标注的符合程度。
- **优化目标**：`G* = argmax_G E_{(s_i,y_i)~D_align}[1{RCAEngine(s_i, G) = y_i}]`，即在对齐集上最大化精确匹配率。

#### 理论性质

- **命题1（单调精炼）**：随着标注事件增加，根因一致图集单调不增（`C_{m+1} ⊆ C_m`），更多反馈只会消除候选图。
- **命题2（训练集RCA不变性）**：`C_RCC` 中的所有图在训练集上产生相同预测，但可能在未见事件上产生分歧——即训练集一致性不足以唯一确定泛化最好的图。
- **可识别性充分条件**：若骨架已知、标签无噪声、且对每条骨架边都有"边隔离事件"（`V_i = {u,v}`），则根因一致图集退化为单例。但该条件较强，TeleRCA中不满足，因此EvoCause以任务级识别为目标而非唯一DAG恢复。

### 6. 论文的主要结论与发现

- **EvoCause显著提升RCA性能**：在合成数据上以PC初始化时，Node F1提升11.59个百分点（52.03%→63.62%），Case EM提升9.40个百分点（17.80%→27.20%），Graph F1提升4.59个百分点，nSHD降低0.2379。
- **对初始图选择鲁棒**：以PC、NOTEARS、THPs三种差异显著的发现算法初始化，EvoCause在TeleRCA上收敛到几乎相同的性能（Node F1约92.5%，Case EM约89.5%），说明标签反馈对齐有效降低了对初始发现偏倚的依赖。
- **超越所有非EvoCause基线**：在TeleRCA上，EvoCause-PC达到Node F1=92.58%、Case EM=89.61%，显著超过最佳的APGNN基线（84.14% / 78.30%）。
- **告警标题语义信息有实质贡献**：匿名化告警标题后Node F1下降6.12个百分点、Case EM下降8.04个百分点；但匿名变体仍超过最强非EvoCause基线，说明即使无语义信息，结构反馈引导仍然有效。
- **合成数据上无语义也能优化**：数字标识符条件下性能仍有提升，证明EvoCause可以从源集失配和图上下文中提取有效信号。
- **拓扑序上下文贡献大于优化历史**：组件消融显示移除拓扑序导致Node F1下降2.90个百分点，而移除优化历史仅下降0.81个百分点。

### 7. 优点

- **问题建模清晰**：将专家根因标签形式化为"源节点约束"，定义了根因一致图集（RCC），并明确分析了可识别性条件，理论框架严谨。
- **发现无关（discovery-agnostic）**：EvoCause将因果发现算法视为黑盒，可以精炼任何算法输出的图，无需修改其内部学习过程，通用性强。
- **LLM角色定位合理**：LLM仅做图编辑提议（组合搜索空间的智能化缩小），不直接预测根因，不做最终决策；确定性代码负责校验和择优，职责分离降低了LLM幻觉带来的风险。
- **推理阶段无LLM依赖**：测试时仅使用精炼图做透明推理，零LLM调用，适合生产环境的延迟和成本约束，且预测可审计、可解释。
- **发布真实基准数据**：TeleRCA是来自生产电信网络的大规模专家标注基准（10,922事件/48.5万告警），为后续研究提供了稀缺的公共测试平台。
- **消融设计有针对性**：匿名化对比实验精准分离了语义信息与结构反馈的贡献，实验设计具有方法论的参考价值。

### 8. 不足与局限

- **可识别性不强**：作者承认专家标签通常只能确定根因一致图集合而非唯一DAG，训练集的一致性无法保证未知事件上的泛化差异，缺乏更强的理论保证。
- **假设条件理想化**：三个核心假设（因果一致性、因果充分性、专家标签一致性）在实际电信场景中未必成立——潜在共同原因和资源特定的传播变化都是现实存在的，标签噪声也在所难免。
- **报错鲁棒性分析较浅**：虽然给出了标签噪声的有界影响公式，但未实验验证存在系统性标签偏差时的行为；对大量噪声标签下的性能退化缺乏实证。
