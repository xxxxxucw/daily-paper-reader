Abstract
In-context learning (ICL) lets tabular foundation models make predictions with-
out dataset-specific training or fine-tuning. These models achieve strong predic-
tive accuracy, but interpreting how individual features contribute to the prediction
remains difficult. In biology, for example, feature contributions can help identify
biomarkers or risk genes. Post-hoc interpretability methods assign feature impor-
tance scores, but these scores do not indicate what the model actually uses and
can lead to explanation errors. We introduce TICL3 (Tabular In-Context Local
Linear Learning), an interpretable-by-design predictor that uses a tabular founda-
tion model to guide a simple linear prediction rule. TICL3 first learns a shared
linear model to capture dataset-level feature effects. Then, for each query, it re-
trieves similar training samples using representations from the foundation model
and fits a second linear model to the residuals in that neighborhood. The shared
model captures broad effects, while the local model corrects errors among similar
samples. Their combined coefficients determine each feature contribution to the
final query-specific linear score, so the same model makes and explains the pre-
diction. Across 386 classification benchmark–dataset evaluations, TICL3 trails
TABICLV2 by 1.1 percentage points and outperforms CatBoost in 266 evalua-
tions. It improves average support F1 over MAPLE by 4.7 points and achieves the
best performance on both real-data selected-feature utility metrics.

Introduction
Making predictions on tabular data remains a challenge in machine learning, where interpretability
of individual predictions is often as important as predictive accuracy. Classical algorithms, includ-
ing sparse linear models, generalized additive models (GAMs), and explainable boosting machines
(EBMs) [1], provide explicit feature contributions, although their structural constraints may limit
predictive performance. Recent tabular foundation models [2, 3] adopt a different paradigm by
leveraging labeled examples as context to predict new samples without requiring dataset-specific
parameter updates. Related in-context regression approaches have also been extended to reinforce-
ment learning [4]. While these models show strong predictive performance, multiple attention layers
complicate attributing individual input feature contributions to each prediction.
Post-hoc interpretability methods such as LIME [5] and SHAP [6] explain predictors after training.
Other approaches include gradient-based attribution methods [7, 8], FastSHAP [9], and learned local
surrogate models [10]. While these methods can provide useful feature importance scores, they do
not use these scores to make predictions and may not fully reflect how the model uses each feature.
TICL3 is introduced as an interpretable-by-design predictor that leverages a tabular foundation
model to infer a simple prediction rule. First, we train a shared ElasticNet [11] to learn a dataset-
wide rule based on the foundation model’s predictions. For each query, the foundation model’s
embedding identifies similar training samples, referred to as a neighborhood. We then fit a second
ElasticNet to the residuals between the foundation model’s predictions and the shared rule within

The central idea of TICL3 is to use the foundation model’s learned representation to inform lo-
cal correction fitting, with explicit coefficients specifying the prediction process. Table 1 compares
TICL3 with existing methods. In TICL3, we derive feature contributions directly from the linear
model used to compute each class score, rather than from a separate explanation technique. When
combined with a baseline, these contributions sum precisely to the class score. The model further
employs representations learned through tabular in-context learning (ICL) to select relevant training
samples. However, these contributions do not elucidate how individual features influence sample
selection or the determination of fitted coefficients. Figure 1 compares prediction accuracy, expla-
nation quality, and computational cost.
For each query, we form a single linear model that is composed of the shared and local models.
The coefficients, together with the processed feature values, determine each feature’s contribution
to the prediction score for a class, and we map these contributions back to the original columns of
the table. We use an ElasticNet regularizer to encourage a sparse coefficient vector. The foundation
model does not make the final prediction; it provides targets to fit the shared prediction rule and
selects the rows to use for each query. The final prediction is made by the explicit prediction rule
described above. The error in this local approximation can be bounded in terms of (i) smoothness
of the residual, (ii) context shift, (iii) the radius of the neighborhood in the representation space, (iv)
distance of the query to the weighted feature centroid, and (v) the amount of regularization.

Background and Related Work
We group related work into three categories: predictive models, post-hoc explanation methods, and
interpretable-by-design models.
Predictive models.
Tabular ICL models such as TabPFN [2], TabPFNv2 [19], and TABICLV2 [12]
demonstrate strong predictive performance, as do task-specific neural models like TabM and
TabR [20, 21]. Some approaches combine neural and tree-based encoders to learn tabular repre-
sentations [22]. While these models learn effective representations and prediction functions, they do
not provide explicit feature contributions that directly determine predictions.
Post-hoc explanation methods.
LIME [5], SHAP [6], gradient attributions [7, 8], and learned
explainers clarify the outputs of a fixed predictor. ExplainerPFN [13] uses a pretrained tabular
foundation model to estimate feature attributions for a new dataset without access to the explained
predictor. These methods offer feature attributions or local approximations, but their explanations
do not determine the final prediction.
Interpretable-by-design models.
Lasso [23], EBMs [1], and NAMs [14] use explicit feature con-
tributions within a shared model. LOESS [24] and MAPLE [15] fit local linear rules, defining
neighborhoods or sample weights by input distances or tree-based representations. LSPIN and its
locally linear variant LLSPIN [16] train a gating network that selects a sparse feature subset for
each sample; with a linear prediction network, LLSPIN deploys a sample-specific sparse linear rule.
ShapPFN [18] makes a tabular foundation model’s prediction additive over per-feature contributions,
although each contribution is computed by the transformer rather than by an explicit feature-level
rule. Context-dependent feature-selection methods allow selected variables to vary with the ob-
served context [25]. However, these methods do not leverage context-conditioned representations
from a pretrained tabular ICL model to fit a query-specific prediction rule.
TICL3 uses representations from a tabular ICL model to select a neighborhood for each query and
fits a local linear correction to the residuals of a shared linear predictor. The combined coefficients
directly determine the prediction. For more details on related work, see Appendix F.
3
Method
For a new test query, TICL3 constructs an adaptive linear prediction rule using representations from
a tabular foundation model. The representations allow TICL3 to identify the training samples that
are most relevant to the test query. The coefficients, together with the processed feature values and
intercept, determine the class scores and feature contributions. We consider two variants of TICL3,
TICL3 (global + residual) and TICL3 (regional anchors). In TICL3 (global + residual), we first
fit a shared linear prediction model to capture the global effects of features. Then, for each test
query, we use the representations to find training samples similar to the query and fit a second linear
prediction model to the shared model’s residuals on these samples. The final prediction rule for the
test query consists of the sum of the shared linear model and the query-specific linear model. In
TICL3 (regional anchors), we avoid fitting a new prediction model for each test query by fitting
regional prediction models upfront and combining them based on their similarity to the query. See

Optimization. We solve the two ElasticNet problems with weighted centering to allow for an un-
regularized intercept, optimizing each coefficient matrix jointly across classes with FISTA [26] with
backtracking line search and checking the KKT residual, for at most 300 iterations with tolerance
10−4. When solving for the coefficients of the shared model, all rows of the reference set are
weighted equally, and when solving for the query-specific correction, we weight the rows according
to equation 1.
Implementation details. For the primary configuration (global residual), we use one TABICLV2
estimator for test-query predictions, using float32 precision (not automatic mixed precision). We
use the class probabilities directly as the target when fitting the shared model (there is no label
smoothing). When computing the representation, we use a single view at the input to the first
ICL decoder block; when retrieving neighbors, we use a cached, cross-fitted reference bank (see
appendix B) and exact top-k retrieval.
Our primary configuration uses k = 400 and τ = 0.1; α = 0.01 and ρ = 0.25 at both stages
(implying ℓ1 coefficient αρ = 0.0025, ridge weight α(1 −ρ) = 0.0075, and the coefficient on
∥A∥2

weight them according to their representations. We use squared loss.
Regional anchor variant.
In TICL3 (regional anchors), we fit local linear models in advance
rather than fitting a new model for each query. We cluster the reference-bank representations and
select the training sample closest to each cluster center as an anchor. For each anchor, we fit an Elas-
ticNet using nearby reference samples and their backbone probability targets. Unlike TICL3 (global
+ residual), these models are fitted directly to the backbone predictions rather than to residuals of a
shared model. For a new query, we use its backbone representation to weight the coefficients and
intercepts of the pre-fitted models. Their weighted combination gives a query-specific linear rule for
prediction and feature contributions, without fitting a new model at prediction time (Appendix E.5).
4
Experiments
We evaluate three qualities of TICL3: whether the deployed global-plus-local predictor remains
a competitive tabular classifier; whether its combined coefficients rank data-generating features
when the generating support is known; and the deletion monotonicity, selected-feature utility, and
stability of its centered contributions on real-world datasets. Predictive performance is evaluated
on 386 benchmark–dataset pairs across four classification benchmarks: CC-18 [27] (69 datasets),
TabArena-Lite [28] (38), TALENT [29] (181), and BeyondArena [30] (98). We evaluate feature-
selection quality on controlled synthetic tasks with designated generating supports. Real-data inter-
pretability is evaluated on a fixed CC-18 subset, with regional explanation diagnostics confined to
Appendix E.5.

On the ten explanation-benchmark datasets, adding
a local correction increases the shared model’s accuracy from 76.13% to 89.90%. However, the

accuracy is lower, so we need to consider them together with accuracy.
When compared with the local-only model using the same k = 400, the combined model has

monotonicity in the paired comparison. However, the combined model gives a nonzero explanation

Using k = 400 rather than k = 30 improves paired deletion Spearman by 0.130 (95% interval

4.6
Limitations and Future Work
TICL3 (global + residual) is limited by the expressiveness of the linear model, and may struggle
to capture highly interactive local residual functions in the retrieved neighborhood, particularly for
higher-dimensional and multi-class problems. Our approach does not directly model categorical
features, and we ordinally encode any categorical columns before treating them as numerical. As a
result, our feature contributions are for the entire encoded column, rather than for specific categories.
Handling categorical features directly and providing attributions for groups of categorical features
could improve the interpretability of TICL3 (global + residual) in this setting. Similarly, we do
not currently evaluate our approach on text input. We leave evaluating TICL3 (global + residual)
with direct categorical handling and on text inputs, and augmenting the approach with richer local
interpretable model components, to future work.
While our provided feature contributions exactly decompose the query-specific linear score, our
explanations do not decompose the final normalized probability score or account for how features
influence the learned representation, retrieval, and the fitted coefficients. Sparsity in the learned
coefficients does not imply that the entire query-adaptive model only depends on the features with
nonzero coefficients. Our retrieval approach (top-k) can also introduce discontinuities into our ex-
planations, which can shift substantially based on small changes in the query point; the active set
for ElasticNet may also vary. Further, our regional anchor model approach often does not provide a
feature-level explanation, as the coefficients for the blended model (corresponding to the predicted
class) are all zeros for 73.3% of queries on the synthetic data and 43.8% on real data.
Our real data interpretability study is limited to a single backbone model and a fixed subset of 10
datasets in a capped low-data regime. The studied metrics do not establish causal feature relevance;
notably, Gen-SVM can utilize both the locations and values of retained features. Additionally, the
gradient-based rows utilize a differentiable surrogate with unquantified approximation error. We
also do not evaluate the interpretability of our regression approach. Our methods also require access
to the internal representations of the tabular in-context learning backbone, and do not apply directly
to fully black-box models.
5
Conclusion
We propose TICL3 (global + residual), an interpretable-by-design predictor leveraging a tabular
foundation model to guide a linear predictor. TICL3 (global + residual) learns a single ElasticNet
model to capture global feature effects, and leverages the tabular foundation model to retrieve a
similar set of samples for each query, learning a second ElasticNet to capture the residuals of the
first. Together, these produce a query-specific linear prediction rule. TICL3 (global + residual)
provides feature contributions and a baseline that exactly sum to the linear prediction score for
each class. We theoretically bound TICL3 (global + residual)’s local approximation error, under a
smoothness assumption on the residual in the learned representation space that includes an additive
term for differences between labeled contexts.
Across four classification benchmarks, TICL3 (global + residual) is competitive with the TABI-
CLV2 backbone (within 0.3 to 1.6 percentage points in accuracy) and outperforms the strongest
10


tree-based baseline on each. Across a synthetic benchmark for feature selection, TICL3 (global +
residual) is the top-performing interpretable predictor among those evaluated on average in support
F1 score. On the real-data explanation benchmark, TICL3 (global + residual) scores highest among
the evaluated methods on two metrics measuring the utility of the selected features, and second
on a metric measuring deletion monotonicity. We also propose TICL3 (regional anchors), which
combines pre-fitted regional linear models; TICL3 (regional anchors) is slower than a compara-
ble single-estimator backbone model, but faster than the corresponding eight-estimator backbone
model.
Our approach is limited by the fact that our explanations are only for the linear class scores, and
by the expressiveness of local linear models. We leave exploring richer local interpretable models,
leveraging additional tabular foundation models, and evaluating our approach’s explanation quality
for regression to future work.

A
Broader Impacts
Positive impacts.
Interpretable machine learning is especially valuable in high-stakes decision
domains such as healthcare, credit scoring, and legal risk assessment, where practitioners need to
understand and audit individual predictions. TICL3 lowers the barrier to inspecting tabular predic-
tions by producing additive per-feature contributions directly, without a separate post-hoc explainer
pipeline. Such decompositions may make it easier for domain experts and regulators to audit model
behaviour, provided that their empirical fidelity and stability are validated for the deployed configu-
ration.
Negative impacts.
Like other prediction and explanation tools, the method may be misused in
high-stakes settings or lend unwarranted confidence to automated decisions. Practitioners may also
over-interpret coefficients as causal evidence rather than predictive associations. We frame them
explicitly as contributions to the deployed query-specific linear score; they do not separately decom-
pose representation-based retrieval, coefficient fitting, or the clipping-and-normalization step, and
they do not imply causality.
B
Reference-Bank Construction
The reference bank is constructed once for each training split using five-fold stratified cross-fitting.
We partition the training rows into five folds. For each fold, we fit the backbone on the other four
folds, present the held-out rows as unlabeled queries, and record their class probabilities and repre-
sentations at the input to the first ICL decoder block. Concatenating the held-out outputs gives every
training row one out-of-fold probability target and one query-role representation. This prevents a
row’s target and representation from being produced by a backbone that was fitted on that row’s
label, and it places reference rows in the same unlabeled-query role used at test time. A separate
backbone fitted to the complete training split supplies test-query representations. The folds are used
only to construct the reference bank; they do not create an ensemble of deployed predictors. The
processed design vectors used by both ElasticNet stages are constructed with the complete-training
preprocessing map. The retained-column mask, processed-coordinate order, and raw-column origin
map are then held fixed; fold-specific backbones provide out-of-fold targets and representations, not
alternative linear-design coordinates. Thus a stored row and a test query enter the linear rule in the
same processed feature space even though their representations are obtained under different labeled
contexts. Cross-fitting prevents direct label leakage and places each reference row in an unlabeled-
query role, but it does not guarantee that representations produced under different fold contexts are
directly comparable to one another or to a test representation produced under the complete con-
text. Theorem 1 therefore states the required compatibility condition on the actual context-specific
outputs and includes an additive term for the resulting cross-context shift.

E.7
Explanation Baselines and Deletion Protocol
The post-hoc explanation methods and TICL3 (global + residual) target the same complete TICL3
(global + residual) wrapper; TICL3 (regional anchors) targets its own deployed regional wrapper.
They are evaluated on the same ordered query blocks, with the same masking operator and the same
fill value for a removed feature: the training-set mean of that raw feature on the corresponding
split. The class predicted by the relevant unperturbed wrapper is frozen and used as the explained
class for class-specific methods. Features are ranked once per query and removed cumulatively in
that order to a depth of min(10, Draw), and we record the drop in the frozen-class probability after
each step. During a perturbation, the original ordered query block is fixed and only the focal row
is replaced. Prediction calls rerun the full relevant wrapper because the query representation and,
for TICL3 (global + residual), the neighborhood and residual correction may change. This is a
deployment-oriented benchmark rather than a test of causal relevance.

Additional Background and Related Work
We organize prior work along three axes that are central to this paper: whether the predictor is
interpretable by design or requires post-hoc analysis, whether the predictive form exposes explicit
feature contributions, and whether predictions adapt locally to each query. We distinguish post-hoc
explanations, which analyze a fixed predictor after inference, from interpretability by design, where
the prediction itself is computed through an inspectable structure. Table 1 summarizes representative
methods under this view and positions TICL3 as an interpretable-by-design, global-plus-local linear
predictor.
Tabular in-context learning models.
Recent work has introduced a new paradigm for tabular
prediction in which a labeled dataset is provided as context at inference time. Given a labeled
context {(xi, yi)}N

in a single forward pass, without dataset-specific training. Here y∗is the unknown query label, θ
denotes the pretrained model parameters, and pθ(· | ·) is the resulting conditional class distribu-
tion. This corresponds to in-context learning, in which adaptation to a new task is performed by
conditioning on labeled examples rather than by gradient updates.
During pretraining, models are exposed to a distribution of datasets and optimized to predict labels
for held-out examples given their context, encouraging a general-purpose inference procedure. Ar-
chitecturally, different designs vary in how tabular data is represented and how interactions are
modeled.
TabPFN [2] represents rows as tokens and performs attention across samples, while
TabPFNv2 [19] introduces a cell-based design with alternating row and column attention, increas-
ing flexibility at a higher computational cost. TABICL [3] improves scalability through a two-stage
design that first constructs row embeddings and then performs attention over them. Throughout this
work, we use TABICLV2 [12], the successor of TABICL, as our backbone and primary baseline.
These models are strong predictors, but their decision-making process is not interpretable by design:
predictions are computed via multi-layer attention rather than through explicit feature-level opera-
tions. In Table 1, they therefore lie outside the interpretable-by-design, linear, and local region.
Rather than attempting to explain these models post hoc, TICL3 reuses their context-conditioned
representation geometry to define locality, while constructing a separate predictor whose computa-
tion is interpretable by design.
Post-hoc local explanation methods.
Post-hoc explanation methods approximate a trained pre-
dictor after it has produced a prediction. Model-agnostic approaches such as LIME [5] and SHAP [6]
construct local surrogate models or estimate feature attributions by perturbing the input. These meth-
ods operate at the input-output level and do not expose the internal computation that produces the
prediction. As a result, they require repeated evaluations of an external predictor and define locality
independently of its internal representation.
Gradient-based attribution methods, including Integrated Gradients [7], DeepLIFT and Input × Gra-
dient [8], and GradientSHAP-style estimators [44], instead use differentiability to assign feature im-
portance scores. A separate line of work amortizes explanation through learned selector–predictor
models that return instance-wise feature subsets, including L2X [45], INVASE [46], REAL-X [47],
and FastSHAP [9]; ILLUME [10] similarly learns meta-representations for local surrogate explana-
tions. LIME, SHAP, and gradient attribution analyze a fixed predictor after inference. The original
L2X, INVASE, and REAL-X formulations instead train selector and predictor components jointly
or in coordinated objectives; our Table 5 adaptations train their selectors against the fixed TICL3
(global + residual) wrapper outputs. In each case, the selector or explainer score is distinct from the
explicit rule used by that wrapper to make its prediction.
Interpretable-by-design models and local predictors.
Interpretable-by-design models expose
feature-level structure directly in the deployed predictor. Classic examples include sparse linear
models, such as Least Absolute Shrinkage and Selection Operator (Lasso) [23], and additive mod-
els, such as Explainable Boosting Machines (EBMs) and Neural Additive Models (NAMs) [1, 14].
These models are interpretable by design and often partially linear, but they are typically global: a
single model is applied across all queries.
23


Local modeling approaches instead fit simple predictors in a neighborhood around each query.
Methods such as LOESS [24] and local polynomial regression [48] often use input-space distance.
MAPLE [15] learns a supervised forest geometry and derives query-dependent proximity weights
before fitting a local model. Its forest is fixed after training, but its neighborhood is label-informed
and changes with the query. In contrast, TICL3 recomputes neighborhoods from representations
conditioned on the current labeled ICL context; the distinction is the context-conditioned geometry,
not an absence of query adaptation in MAPLE.
LSPIN and its locally linear variant LLSPIN [16] obtain query adaptation differently. Building on
stochastic-gate feature selection [49], a gating network trained jointly with the prediction network
maps each sample to gates that select a sparse subset of its features. When the prediction network is
linear (LLSPIN), the deployed model is a sample-specific sparse linear rule whose coefficients are
the shared weights multiplied by the sample’s gates. Locality is thus learned from the labels by a
dataset-specific gating network, whereas TICL3 obtains it from the representation of a pretrained in-
context model and fits each local rule with a per-query ElasticNet. Our synthetic tasks and selected-
feature utility metrics are adapted from this work (Section 4.3 and Appendix E.8).
TICL3 differs from these prior directions in how locality is defined and reused. A shared ElasticNet
model captures dataset-level structure, while context-conditioned representations from a pretrained
tabular in-context learner determine which training rows fit each query’s residual correction. The
deployed predictor is the sum of this global coefficient matrix and a query-specific ElasticNet cor-
rection in the processed feature space. It is therefore interpretable by design and query-adaptive,
with locality grounded in the foundation model’s learned geometry rather than raw input distances.
Interpretable extensions of tabular in-context models.
Recent work has explored incorporating
explanations directly into tabular in-context models. ShapPFN [18], a TabPFN-style model pre-
trained on synthetic datasets, decodes a base term and per-feature, per-class contributions from the
test-row embeddings and sums them to obtain its logits. Its prediction is therefore additive over
features by construction, and predictions and contributions are produced in a single forward pass.
ExplainerPFN [13] instead targets model-free feature-importance estimation: it predicts Shapley-
style attributions for a new dataset without access to the model being explained.
ShapPFN is interpretable by design in the additive sense of Table 1, because its displayed contri-
butions sum to its output. Each contribution, however, is computed by attention layers over the
full labeled context, so how a term depends on its feature value is not itself inspectable, and no
explicit feature-level rule is deployed. In TICL3, the contribution of processed feature j to class c
is the product (z∗
j −zj)W ∗
j,c of the centered feature value and an explicit coefficient; the founda-
tion model only supplies prediction targets and defines the neighborhood. ExplainerPFN, like other
post-hoc methods, produces attributions that do not determine a deployed prediction.
Example-based explanations.
Example-based methods explain predictions by identifying simi-
lar training instances, as in prototype and metric-based approaches [50]. These methods provide
sample-level evidence but do not produce explicit feature-level contributions. TICL3 retains the
neighborhood view but uses it to adapt a shared linear predictor through a residual correction, yield-
ing both sample-level locality and feature-level contributions within a single interpretable-by-design
model.
